# Портфолио лендингов + 4 готовых лендинга

Статический сайт без сборки и зависимостей: чистый HTML + CSS + JS.
Открывается двойным кликом, заливается на GitHub Pages за 2 минуты.

**В портфолио намеренно нет имени, контактов и форм** — это витрина работ,
которую можно пересылать клиентам и показывать от имени любого человека.
Все контакты и заявки живут внутри самих лендингов — там, где им и место.

## Что умеют лендинги

Каждый лендинг — полноценная страница, а не макет, и **у каждого своя вёрстка**:
шаурмячная собрана как bento-сетка с фото-героем во всю ширину, салон красоты —
как редакционный журнал с линейками и лентой работ, автосервис — как техническая
документация с моно-разметкой, стоматология — как фотоколлаж с вертикальными карточками.

Общее у них:

- адаптив от 320 px до широких мониторов;
- фиксированная шапка + мобильное меню + липкая нижняя кнопка на телефоне;
- появление блоков при скролле, счётчики, бегущие строки;
- аккордеон FAQ, формы с валидацией, маской телефона и экраном «заявка отправлена»;
- **интерактивные блоки**:
  - шаурмячная — конструктор заказа с живым пересчётом цены;
  - автосервис — калькулятор ТО с коэффициентами по марке и объёму двигателя;
  - салон и стоматология — онлайн-запись с выбором мастера, услуги и даты.

## Фотографии

Все фото в папках `sites/*/img/` взяты со **StockSnap.io** — это бесплатные
фотографии под лицензией **CC0** (общественное достояние). Можно использовать
свободно, без указания авторства.

| Лендинг | Количество |
|---|---|
| Шаурмячная | 11 |
| Салон красоты | 9 |
| Автосервис | 8 |
| Стоматология | 6 |

Перед публикацией замени их на реальные фотографии заведений — обычно это
поднимает конверсию сильнее, чем любые правки вёрстки.

Замена: положи файл в `sites/<название>/img/` с тем же именем
или поправь `src` в разметке. Каталог задаёт пропорции кадра
(`aspect-ratio`) и режим кадрирования (`object-fit: cover`), так что
подойдёт фото любой ориентации.

## Как запустить локально

Нужен любой локальный сервер (прямое открытие `index.html` через `file://` ломает превью в iframe).

```bash
# вариант 1 — Node.js
npx http-server -p 5173 -c-1 .

# вариант 2 — Python
python -m http.server 5173
```

Открыть `http://127.0.0.1:5173`.

## Как задеплоить на GitHub Pages

Git и `gh` на этой машине **не установлены**, поэтому есть готовый скрипт,
который работает на чистом Node.js через GitHub REST API.

### Шаг 1. Создай токен

GitHub → **Settings** → **Developer settings** → **Personal access tokens** →
**Fine-grained tokens** → **Generate new token**:

- Repository access: **Only select repositories** → выбери нужный
  (или сначала создай пустой репозиторий и выбери его)
- Permissions → **Contents**: **Read and write**
- срок жизни — любой

Скопируй токен (начинается с `github_pat_`).

### Шаг 2. Запусти деплой

```bash
node deploy.mjs --user ТВОЙ_НИК --repo lendings --token ТВОЙ_ТОКЕН
```

Скрипт сам:

1. создаст репозиторий, если его ещё нет;
2. загрузит все 49 файлов (5,6 МБ) как Git-объекты;
3. соберёт ветку `gh-pages` и коммит;
4. включит GitHub Pages на этой ветке;
5. дождётся сборки и напечатает ссылку.

Чтобы ничего не отправлять и просто посмотреть состав загрузки:

```bash
node deploy.mjs --dry-run
```

Чтобы репозиторий был публичным: добавь флаг `--public`.

### Альтернатива: обычный git

Если git установлен, всё тоже делается в три команды:

```bash
git init && git add . && git commit -m "портфолио"
git branch -M main
git remote add origin https://github.com/ТВОЙ_НИК/lendings.git
git push -u origin main
git subtree push --prefix . origin gh-pages
```

Дальше: **Settings → Pages → Source → ветка `gh-pages`, папка `/ (root)`**.

### Вариант через Actions

Создай `.github/workflows/pages.yml`:

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: pages
  cancel-in-progress: true
jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: '.'
      - id: deployment
        uses: actions/deploy-pages@v4
```

И в **Settings → Pages → Source** выбрать **GitHub Actions**.

> Файл `.nojekyll` уже добавлен — без него Jekyll на GitHub Pages может вырезать
> папки, начинающиеся с `_`, и испортить пути.

## Что заменить перед публикацией

Все контакты в портфолио демонстрационные — их там нет. Проверь только содержание:

| Что | Где искать |
|---|---|
| Цифры в кейсах (+38%, 21 000 ₽, 3.4× …) | `index.html`, секция `#works` |
| Отзывы клиентов и имена | `index.html`, секция `#clients` |
| Стоимость и сроки | `index.html`, секция `#price` |
| Формулировки в FAQ | `index.html`, секция с аккордеоном |
| Телефоны, адреса и цены заведений | `sites/*/index.html` — шапка, меню и подвал каждого лендинга |

Массовая замена телефонов/адресов (пример для демо-заведений):

```powershell
Get-ChildItem -Recurse -Include *.html,*.css,*.js |
  ForEach-Object {
    (Get-Content $_.FullName -Raw -Encoding UTF8) `
      -replace '\+7 900 123-45-67', '+7 999 123-45-67' |
    Set-Content $_.FullName -Encoding UTF8
  }
```

## Как подключить формы лендингов к реальному приёму заявок

Формы есть только **внутри лендингов**. Сейчас они показывают экран «Заявка отправлена» и ничего никуда не шлют — сделано, чтобы сайт работал без бэкенда.

**Вариант A. Telegram-бот (бесплатно, 5 минут)**

1. Создай бота у `@BotFather`, получи токен.
2. Узнай свой `chat_id` (напиши боту, открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates`).
3. Добавь маленький скрипт в конец `<body>` нужной формы:

```html
<script>
document.querySelector('form[data-demo-form]').addEventListener('submit', async function (e) {
  e.preventDefault();
  const data = Object.fromEntries(new FormData(this));
  await fetch('https://api.telegram.org/bot<ТОКЕН>/sendMessage', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      chat_id: '<CHAT_ID>',
      text: 'Новая заявка с сайта:\n' +
            Object.entries(data).map(([k, v]) => `${k}: ${v}`).join('\n')
    })
  });
  document.getElementById(this.dataset.ok).classList.add('is-on');
});
</script>
```

**Вариант B. Почта.** Подойдёт [Formspree](https://formspree.io) или [Getform](https://getform.io): в `action` формы вставить свою ссылку, в JS заменить `e.preventDefault()` на отправку в `fetch`.

**Вариант C. CRM.** Аналогично — принимай `fetch`ом и прокинь в amoCRM / Bitrix24 через их REST API.

## Как поменять цвета лендинга

В начале `sites/<название>/style.css` есть блок `:root` с переменными:

```css
:root {
  --bg: #100b09;        /* фон */
  --brand: #ff5a1f;     /* основной акцент (кнопки, ссылки) */
  --accent: #ffc42e;    /* вторичный акцент (цены, бейджи) */
  --font-display: 'Oswald', sans-serif;
}
```

Поменяешь `--brand` — перекрасится вся страница. Шрифты подключаются в `<head>` каждого лендинга через Google Fonts.

## Как добавить реальные фотографии

Сейчас вместо фото используются векторные иллюстрации — они не ломаются и весят мало. Чтобы поставить свои:

```html
<div class="art">
  <img src="assets/photo.jpg" alt="Наш зал">
</div>
```

`.art` задаёт скругление и соотношение сторон, картинка растянется по контейнеру.

## Браузеры

Проверено в актуальных Chrome, Edge, Firefox и Safari. На старых Safari (< 14) не будет работать `backdrop-filter` (стекло шапки станет просто плотным фоном) — на конверсию это не влияет.

В коде есть `prefers-reduced-motion`: если в системе включено «меньше движения», анимации отключаются автоматически.
